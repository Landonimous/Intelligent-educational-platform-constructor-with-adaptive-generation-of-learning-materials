### Выводы по обзору

Для каждой части будущей платформы есть своя научная база, однако развивались эти части порознь. IRT пригодна для подбора заданий не только в тестировании, но и в обучении, хотя для этого нужны доработки и данные для оценки трудности заданий [1, 2, 10]. В первой версии системы разумно взять простую модель, поскольку модель Раша уже использовали на российских школьных данных, а усложнение модели, например ради учёта угадывания, не всегда оправдано [8, 9]. Более гибкие модели знаний ученика, от байесовской трассировки до нейронных сетей, можно рассмотреть позже, когда накопится достаточно данных [3, 4].

Генерацию вариантов заданий для математики описывают двумя способами. Первый меняет параметры шаблона, второй опирается на систему компьютерной алгебры [7, 12]. Проверку программных заданий изучают давно, а студенческая платформа 2026 года показывает, как изолировать код в Docker-контейнерах с лимитами времени и памяти [5, 11]. Математические ответы нельзя сравнивать как строки, и для проверки их эквивалентности подходит библиотека SymPy [6].

В изученных работах эти компоненты рассматриваются отдельно, и единой системы не описано. Нет работы, где один шаблон задания порождает вариант, подбирается под уровень ученика и проверяется автоматически и для программирования, и для математики. Кроме того, остаётся неясно, как оценить начальную трудность заданий у репетитора, у которого нет большой выборки ответов. На эти два вопроса и опирается содержание ВКР.

## 3. Обзор и сравнение аналогов

### Прямые аналоги

**Stepik** ([habr.com, блог Stepic](https://habr.com/en/companies/stepic/articles/302702)). Облачная платформа онлайн-курсов с автоматической проверкой программных задач. В 2016 году на ней запустили адаптивный курс по Python, который подбирает задачи по уровню ученика, и работают рекомендации уроков. В изученных описаниях не упомянуты проверка эквивалентности математических ответов и генерация вариантов из шаблона, а сама платформа работает как облачный сервис.

**Skysmart Класс** ([skillbox.ru, обзор Skysmart](https://skillbox.ru/media/edtech/kto-est-kto-v-edtech-skysmart/)). Сервис, где учитель создаёт задания и получает их автоматическую проверку. По данным на февраль 2021 года в нём более 150 тысяч заданий и 16 обучающих механик. Адаптивное обучение в обзоре прямо не описано, нет сведений о проверке кода и о самостоятельном развёртывании, а сами данные могли устареть.

**ALEKS** ([mheducation.com](https://www.mheducation.com/prek-12/program/aleks/MKTSP-GAB02M0.html)). Адаптивная программа по математике для 3–12 классов и по химии на основе теории пространств знаний. Сначала проверка определяет, что ученик уже знает, затем строится индивидуальный путь. Программа не рассчитана на задания по программированию, а лицензию выдают по запросу, поэтому репетитор не развернёт её сам.

### Косвенные аналоги

**Moodle с модулем CodeRunner** ([github.com/trampgeek/moodle-qtype_coderunner](https://github.com/trampgeek/moodle-qtype_coderunner)). Тип вопроса для Moodle, который запускает код студента в песочнице и сверяет результат с набором тестов. Распространяется по лицензии GPL-2.0 и требует Moodle 4.3 или новее. Он решает лишь проверку кода и не включает ни адаптацию, ни проверку математических ответов.

**Платформа КузГТУ для обучения программированию** ([science.kuzstu.ru](https://science.kuzstu.ru/wp-content/Events/Conference/RM/2026/RM26/pages/Articles/31223.pdf)). Студенческая разработка 2026 года с каталогом задач, редактором кода, проверкой в Docker-контейнерах и панелью преподавателя. Адаптивного подбора заданий и математики в ней нет.

**Генераторы вариантов заданий** ([ntv.ifmo.ru](https://ntv.ifmo.ru/file/article/4209.pdf), работа Костюченко, и работа Посова, источник 12). Решают задачу генерации заданий, один подход через изменение параметров шаблона, другой через систему компьютерной алгебры. Адаптации и автоматической проверки в них нет.

### Выводы по сравнению

Из существующих решений можно взять проверенные идеи. К ним относятся адаптивный путь с задачами на границе знаний ученика (Stepik, ALEKS), изолированный запуск кода по тестам (CodeRunner, платформа КузГТУ) и изменение параметров шаблона для получения множества заданий (работы Костюченко и Посова).

По доступным описаниям ни одно решение не объединяет все эти функции. Облачные сервисы закрыты для самостоятельного развёртывания, узкие инструменты закрывают только часть задачи, а эквивалентность математических ответов в изученных описаниях не проверяется. ВКР должна устранить эти ограничения единой платформой, где шаблон порождает вариант, система подбирает его по уровню ученика и сама проверяет ответ, а репетитор может запустить сервис на собственной инфраструктуре.

## 4. Итоги

**Итоговая тема ВКР:** Разработка интеллектуальной образовательной платформы-конструктора с адаптивной генерацией учебных материалов и автоматической проверкой решений для подготовки к экзаменам и олимпиадам

**УДК для тезиса:** 004.588

**Ключевые слова:** адаптивное обучение, теория отклика на задание, генерация учебных заданий, автоматическая проверка решений, образовательная платформа, изолированное выполнение кода

### Актуальность исследования

Подготовка индивидуальных заданий остаётся трудоёмкой для репетиторов и онлайн-школ. Если одно задание нужно выдать нескольким ученикам без повторов, преподавателю приходится вручную придумывать десятки вариантов. Поэтому в литературе предлагают создавать их автоматически, меняя параметры шаблона или подключая систему компьютерной алгебры [7, 12].

Стандартный тест одинаков для всех учеников и не учитывает индивидуальный темп освоения материала [10]. Адаптивное тестирование на основе теории отклика на задание описано давно, а модель Раша уже применяли в России на данных ЕГЭ [8, 9]. Работа [1] показывает, что идею можно перенести из тестирования в обучающие среды при условии доработок. Трудность новых заданий приходится оценивать ещё до накопления ответов, и для этого предложено сочетать данные с суждениями экспертов [2].

Автоматическую проверку решений тоже изучали много. Обзор [5] описывает системы проверки программных заданий, а студенческая платформа [11] запускает решения в изолированных Docker-контейнерах с ограничениями по времени и памяти. Математические ответы нельзя сравнивать как строки, поэтому для проверки их эквивалентности подходит библиотека SymPy [6].

Сравнение аналогов показывает, что адаптивность есть в Stepik и ALEKS, проверка кода в Stepik и CodeRunner, а создание заданий преподавателем в Skysmart Класс. Но в изученных описаниях ни одно решение не объединяет параметрическую генерацию, адаптивный подбор, проверку кода и проверку математических ответов в системе, которую репетитор или небольшая школа может развернуть у себя. Накопленная история ответов к тому же позволяет оценивать знания ученика и прогнозировать его результат [3, 4]. Платформа, закрывающая этот пробел, снизит трудозатраты преподавателей при подготовке школьников к экзаменам и олимпиадам.

### Цель исследования

Разработать веб-платформу, которая автоматизирует персонализированную подготовку школьников, от генерации заданий под текущий уровень ученика до автоматической проверки ответов и показа прогресса преподавателю.

### Задачи исследования

1. Проанализировать методы адаптивного обучения и модели знаний ученика, выбрать модель для реализации и обосновать выбор.
2. Спроектировать архитектуру платформы с модулями управления контентом, адаптации, тестирования и изолированной среды выполнения кода.
3. Реализовать конструктор учебных материалов с шаблонами задач и алгоритмом параметрической генерации, который сохраняет структуру решения.
4. Реализовать модуль адаптации с профилем знаний ученика и подбором сложности следующего задания на основе IRT.
5. Реализовать подсистему автоматической проверки решений. Код запускается в Docker-песочнице с тестами на pytest, а математические ответы проверяются на алгебраическую эквивалентность средствами SymPy.
6. Реализовать хранилище событий и панель преподавателя с тепловыми картами ошибок, динамикой скорости решения и оценкой вероятного итогового результата.
7. Провести интеграционное тестирование цепочки «генерация, решение, проверка», апробировать систему на группе учеников и репетиторов и подготовить документацию с руководством по развёртыванию.

### Датасеты и сервисы

Для первой версии внешние наборы данных не обязательны. Банк заданий автор создаст из собственных материалов по математике, физике и информатике, а олимпиадные задачи, если они понадобятся, возьмёт из открытых архивов после проверки условий использования. Модуль адаптации сначала проверят имитационным моделированием ответов учеников с заданными параметрами, а затем реальными данными апробации на группе учеников. Для сравнения моделей знаний можно использовать открытые наборы данных об ответах учеников, например ASSISTments, но условия их использования нужно уточнить.

Из сервисов и библиотек понадобятся SymPy для проверки математических ответов (лицензия BSD), Docker для изоляции кода, pytest для запуска тестов решений и PostgreSQL для хранения данных. Всё это бесплатно и работает на виртуальной машине без внешних платных сервисов.
